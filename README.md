# نظام إدارة نقليات البحص

تطبيق ويب لإدارة حركة نقليات البحص: الرحلات، الأسطول، العملاء، الموردين، الأصناف، والتقارير.

**البيانات مشتركة الآن** عبر قاعدة بيانات حقيقية على Supabase (مجاني) — أي شخص يفتح رابط الموقع، من أي جهاز، يشوف نفس البيانات، وتتحدّث تلقائيًا كل 20 ثانية (أو فورًا بالضغط على زر "تحديث البيانات").

---

## الخطوة 1: إنشاء قاعدة البيانات (مرة واحدة فقط)

1. أنشئ حساب مجاني على [supabase.com](https://supabase.com)
2. من لوحة التحكم: **New Project** → اختر اسم وكلمة مرور لقاعدة البيانات والمنطقة الأقرب لك → أنشئ المشروع (يأخذ دقيقة أو دقيقتين)
3. من القائمة الجانبية: **SQL Editor** → **New query**
4. افتح ملف `supabase/schema.sql` الموجود في هذا المشروع، انسخ كل محتواه، والصقه في المحرر
5. اضغط **Run** — هذا ينشئ كل الجداول المطلوبة (الرحلات، الأسطول، العملاء، الموردين، الأصناف) ويزرع أصناف البحص الأساسية (0، 3/8، 3/4)

## الخطوة 2: ربط المشروع بالمفاتيح

1. من إعدادات مشروع Supabase: **Project Settings → API**
2. انسخ القيمتين: **Project URL** و **anon public key**
3. في جذر هذا المشروع، أنشئ ملف اسمه `.env` (انسخ من `.env.example` الموجود) وضع فيه:

```
VITE_SUPABASE_URL=الرابط_اللي_نسخته
VITE_SUPABASE_ANON_KEY=المفتاح_اللي_نسخته
```

---

## التشغيل محليًا (اختياري، للتجربة قبل الرفع)

يتطلب [Node.js](https://nodejs.org) (نسخة 18 أو أحدث).

```bash
npm install
npm run dev
```

بعدها افتح الرابط اللي يظهر في الطرفية (عادة `http://localhost:5173`).

---

## بناء الملفات الجاهزة للرفع

```bash
npm install
npm run build
```

بعد انتهاء الأمر، بيتكوّن مجلد اسمه **dist** — هذا هو المجلد اللي يحتوي على كل الملفات الجاهزة (HTML/CSS/JS) اللي ترفعها على الاستضافة. لا ترفع باقي الملفات (src، package.json...)، فقط محتويات مجلد dist.

⚠️ ملف `.env` لازم يكون موجود **وقت تنفيذ** `npm run build` (وليس بعده)، لأن Vite يقرأ منه القيم ويضمّها داخل الملفات الناتجة في dist.

## الرفع على استضافة مجانية

### الطريقة الأسهل: Netlify (سحب وإفلات، بدون أوامر)

1. اذهب إلى [app.netlify.com/drop](https://app.netlify.com/drop)
2. اسحب مجلد **dist** (بعد تنفيذ `npm run build`) وأفلته في الصفحة
3. خلال ثوانٍ يعطيك رابط مباشر للموقع يعمل فورًا

> بديل: لو ربطت المستودع من GitHub مباشرة بدل السحب والإفلات، المشروع فيه ملف `netlify.toml` جاهز فيضبط أوامر البناء تلقائيًا — فقط أضف متغيرات البيئة `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` من **Site settings → Environment variables**.

### Vercel

1. أنشئ حساب مجاني على [vercel.com](https://vercel.com)
2. من لوحة التحكم: **Add New → Project** ثم اربطه بمستودع GitHub لهذا المشروع
3. إعدادات البناء (Vite يُكتشف تلقائيًا): Build Command = `npm run build`, Output Directory = `dist`
4. في إعدادات المشروع على Vercel → **Environment Variables**، أضف نفس القيمتين `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`
5. اضغط Deploy

### Cloudflare Pages

نفس فكرة Vercel: اربط المستودع، Build Command = `npm run build`, Output = `dist`، وأضف متغيرات البيئة من إعدادات المشروع.

### GitHub Pages (رفع تلقائي عند كل تعديل)

هذا المشروع يحتوي على أتمتة جاهزة (`.github/workflows/deploy.yml`) تبني وتنشر الموقع تلقائيًا كل مرة تحدّث فيها الكود على فرع `main`.

1. أنشئ مستودع (Repository) جديد على [github.com](https://github.com) وارفع له محتوى هذا المشروع كاملًا (بما فيها مجلد `.github`)
2. من إعدادات المستودع: **Settings → Pages** → في **Source** اختر **GitHub Actions**
3. من إعدادات المستودع: **Settings → Secrets and variables → Actions → New repository secret**، أضف السرّين التاليين (بنفس القيم من `.env` عندك):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. اذهب لتبويب **Actions** في المستودع وتأكد إن الـ workflow اسمه "نشر على GitHub Pages" اشتغل بنجاح (يشتغل تلقائيًا بعد أول رفع، أو شغّله يدويًا من نفس التبويب)
5. بعد ما ينتهي بنجاح، رابط موقعك يكون بالشكل: `https://اسم-المستخدم.github.io/اسم-المستودع/`

من هذه اللحظة، أي تعديل ترفعه على فرع `main` يُبنى ويُنشر تلقائيًا خلال دقيقة أو دقيقتين — بدون أي أمر يدوي.

## ملاحظات مهمة عن الأمان

- هذا الموقع **بدون تسجيل دخول**. أي شخص يعرف رابط الموقع (ومفتاح anon المُضمَّن داخل ملفات الموقع المبنية) يقدر يقرأ ويعدّل البيانات. هذا مناسب لأداة داخلية صغيرة بين فريق موثوق، لكن لا يصلح إذا احتجت صلاحيات مستخدمين مختلفة (مثلاً: موظف يدخل بيانات فقط، ومدير يشوف التقارير فقط) أو حماية أقوى — أخبرني إذا احتجت هذا التوسّع لاحقًا (يتطلب إضافة نظام تسجيل دخول عبر Supabase Auth).
- لا تشارك رابط الموقع علنًا إذا كانت بياناتك حساسة.
- التطبيق مبني بـ React + Vite + Tailwind CSS + Supabase.
